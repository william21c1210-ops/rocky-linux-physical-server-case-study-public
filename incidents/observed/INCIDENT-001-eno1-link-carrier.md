# INCIDENT-001: eno1 Link/Carrier 변화 기록

## 요약

- 관찰일: 2026-08-04
- 대상: `<LAB-SERVER>`의 보조 경로 `eno1`
- 주 경로: `eno4`
- 관찰 증상: 케이블 분리 재시도 뒤 Carrier 0과 `NO-CARRIER`
- 원인 범위: 직접 연결된 `eno1`의 물리 Link
- 현재 상태: 통제한 Link 손실 해소 후 원래 미사용 상태로 종료
- 관련 계획: [`CHANGE-002`](../../changes/CHANGE-002-eno1-link-carrier.md)

시각은 물리 동작의 정확한 순간이 아니라 명령으로 상태를 관찰한 시각이다.

## 타임라인

| 관찰 시각 | 단계 | 관찰 결과 |
|---|---|---|
| 11:00:59 | 운영 원래 상태 | 케이블 없음, Carrier 0 |
| 12:29:42 | 임시 테스트 기준선 | Carrier 1, 1Gbps Full Duplex |
| 12:31:02 | 첫 분리 확인 | Carrier 변화 없음 |
| 12:33:51 | 분리 재시도 확인 | Carrier 0, `NO-CARRIER`, Link 미감지 |
| 12:35:40 | 같은 케이블 재연결 | Carrier 1, 1Gbps Full Duplex |
| 12:39:44 | 테스트 케이블 제거 | Carrier 0인 운영 원래 상태 |

## 첫 분리 확인

12:31:02 확인에서는 Carrier 변화가 없었다.
따라서 이 단계는 의도한 장애가 나타난 것으로 기록하지 않았다.

물리 동작과 조회 사이에 왜 변화가 없었는지는 확인하지 않았다.
확인되지 않은 원인을 케이블, 포트 또는 명령 문제로 단정하지 않았다.

## 재시도와 Layer 1 범위

12:33:51 재시도 뒤 다음 상태가 함께 관찰됐다.

- `eno1` Carrier 0
- `NO-CARRIER`
- Link 미감지

직접 확인한 원인은 노트북 쪽 테스트 케이블 분리에 따른 물리 Link 손실이다.
이 판단을 스위치, VLAN, IP 또는 서비스 계층까지 확대하지 않는다.

## Rollback

분리한 것과 같은 테스트 케이블을 다시 연결했다.
12:35:40에 Carrier 1과 1Gbps Full Duplex를 관찰했다.

이 단계의 목표는 임시 테스트 기준선으로 돌아가는 것이었다.
직접 연결 구간에서는 IPv4 임대를 받지 못했으므로 IPv4 복구를 판정하지 않았다.

## 실험 종료

Rollback 확인 뒤 테스트 케이블을 제거했다.
12:39:44에 `eno1` Carrier 0을 관찰했다.

이는 실험 전 케이블이 없던 미사용 상태로 돌아간 것이다.
Rollback과 테스트 장비 제거는 서로 다른 단계다.

## 주 경로 확인

관찰한 확인 시점에 다음 상태가 유지됐다.

- `eno4` Link
- 외부 목적지 Route의 `eno4` 선택
- `sshd` active
- TCP 22 Listening
- 테스트 종료 뒤 새 SSH 세션 1회 연결

새 세션 한 번은 해당 시점의 한 경로만 확인한다.
모든 사용자와 인증 방식의 무영향을 뜻하지 않는다.

## 확인하지 않은 항목

- `eno1` IPv4 통신
- Gateway Ping과 외부 Ping
- HTTP와 메일 서비스
- 패킷 손실과 지연
- 모든 사용자 영향
- 스위치, VLAN과 전체 물리 토폴로지
- 실제 SSH 장애에서의 iLO 복구

## 결론

상태 흐름은 Carrier 0에서 임시 Carrier 1, 재시도 뒤 Carrier 0,
재연결 뒤 Carrier 1, 테스트 장비 제거 뒤 Carrier 0이었다.

첫 무변화 확인은 성공으로 기록하지 않았고 원인은 미확정으로 남겼다.
확정한 원인은 직접 연결된 테스트 구간의 물리 Link 손실에 한정한다.
